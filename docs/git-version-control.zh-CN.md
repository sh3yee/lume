# Git 版本管理

Lume 桌面应用支持为文件夹工作区创建本地版本，并可将提交推送到远程仓库。设备需要已安装 Git，并且 Lume 能通过系统 PATH 找到 `git`，安装后请重新打开应用。

## 打开版本管理

先打开一个本地文件夹，然后点击文件栏顶部的分支图标，或在命令面板中选择「版本管理」。

已有 Git 仓库会直接显示分支、变更和提交历史。普通文件夹可以点击「启用本地版本管理」创建仓库，原有文件保持原样。

如果工作区只是更大仓库中的一个子目录，面板会显示实际仓库根目录，并限制为查看。要提交或恢复文件，请打开该仓库的根目录作为工作区。

## 切换分支

有其他本地分支时，点击「当前分支」旁的分支名打开菜单。选择目标分支后，Lume 会先保存打开的工作区文档。Git 检测到切换会覆盖现有改动时，会停止切换并给出原因。

切换完成后，文件树、提交历史、推送状态和打开的工作区文档都会刷新。目标分支中缺失的文件会关闭对应的无修改标签页。

## 暂存与提交

「变更」区分已暂存与未暂存文件。点击文件查看对应差异；同一个文件可能同时出现在两个分组中，分别代表已经选入下次提交的内容和后续新修改。

1. 在未暂存文件右侧点击「+」，将该文件当前变更暂存。暂存前会先保存当前工作区中有文件路径的文档；保存失败或存在外部修改冲突时会停止操作。
2. 在已暂存文件右侧点击「−」可以取消该文件的暂存，文件内容保留。
3. 检查已暂存的文件和差异，填写提交说明，点击「提交已暂存内容」。

提交只包含暂存区，不会自动将所有未暂存修改一起提交。未命名草稿不自动加入仓库。已有暂存内容会被识别；打开面板不会主动暂存或取消暂存。暂存某个文件时会纳入该文件当前的全部变更，包括此前没有暂存的部分。

提交作者优先使用现有 Git 配置。如果需要设置，在「提交作者」中填写姓名和邮箱，点击「保存到当前仓库」；此操作只写当前仓库的配置。

如果其他 Git 工具在面板打开后改变了暂存内容，提交会提示重新检查。可点击「刷新」读取实际状态后继续。

## 推送到远程仓库

创建本地提交后，在「版本管理」中点击「连接远程仓库」。可选择已有远程，或填写 HTTPS / SSH 仓库地址。检查目标分支后点击「确认并推送」。首次成功推送会为当前分支设置远程跟踪分支。

已有跟踪分支的工作区会显示待推送的提交数量，点击「推送」即可上传当前分支的提交。远程状态基于最近一次获取或推送，可点击「获取远程状态」刷新。远程有新提交或历史已经分叉时，先用 Git 工具整合更新，再回到 Lume 推送。

认证使用系统 Git 的凭据工具或 SSH 配置。推送失败后可以继续编辑，也可以在解决错误后重试。

「偏好设置 → Git」中的「自动推送」默认关闭。打开工作区后可先设置推送间隔（1 到 1440 分钟，默认 30 分钟），再按需开启。Lume 在运行期间按间隔推送当前分支已提交的内容，并按工作区保存下次推送时间。重新打开工作区时，Lume 会按保存的时间继续等待。如果已经到期，就尝试推送一次，再按设定的间隔安排下一次。首次连接远程和创建本地提交仍由你操作。推送错误会显示在 Git 设置中。

## 查看历史与恢复文件

「历史」按时间展示当前分支的提交，可以加载更多记录。输入仓库相对文件路径，例如 `日记/今天.md`，可筛选该文件的历史；留空查看全部历史。

选择提交，再选择变更文件，可以查看这次提交的差异，或切换到「文件内容」查看该版本的文件。合并提交的差异以第一个父提交为基准；重命名在历史文件列表中可能展示为删除旧路径、新增新路径。

点击「恢复此文件…」后，Lume 会先完成工作区文档保存，并展示具体文件和提交版本。确认恢复会覆盖该文件当前的磁盘内容；需要保留未提交内容时，应先创建提交或备份，再执行恢复。

恢复只替换单个文件，不移动 HEAD，不改写提交历史，也不改变暂存区。恢复结果与当前提交不同时，会成为新的未暂存修改。恢复前会再次检查磁盘文件和打开的文档是否发生变化；有变化时需要重新检查并确认。打开中的文档会同步更新为恢复后的内容。

## 当前范围

- 支持 Markdown、图片和其他普通文件参与版本管理，遵循仓库已有的忽略规则。
- 文本预览要求有效 UTF-8，大小不超过 512 KB；二进制及较大文件可以显示版本信息。Git 单次输出上限为 8 MB，过大的文件恢复或差异查询会提示缩小范围。
- 变更列表最多显示 5000 个文件；超过限制时提示先缩小范围。
- 不恢复符号链接、子模块、Git 元数据路径或越出仓库的路径；目录与子模块的暂存由外部 Git 工具处理。
- 独立 HEAD 状态可以查看历史，切换到本地分支后即可提交。
- 检测到未解决冲突、合并、变基或仓库锁占用时，先使用外部 Git 工具完成处理，再刷新面板。
- 单次 Git 命令有超时限制。Git hooks、签名或其他配置导致提交失败时，面板会显示错误并重新读取实际仓库状态。
- 克隆仓库、将远程更新应用到工作区和解决合并冲突可使用外部 Git 工具。应用内支持的后续安排见[实施规划](git-integration-plan.zh-CN.md)。
