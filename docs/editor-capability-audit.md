# Markdown 能力与右键交互审计

审计日期：2026-10-12。基于提交 `a475084` 的源码、当前安装依赖和独立解析实验。

结论：基础 Markdown 的显示与编辑能力已有实现，但当前不能认定为“完整且经过验收”。主要缺口是两种模式的能力不一致、部分语法在所见即所得保存时不能完整保留，以及右键目标识别和命令语义不统一。

## 验证范围

- 检查项目实际扩展装配、节点解析/序列化、预览渲染、菜单和命令代码。
- 从项目源码提取实际 Preview 函数，使用安装依赖验证基础语法、表格、任务列表、脚注、公式和围栏占位输出。未使用 HTML 的模拟 DOM 来宣称浏览器行为通过。
- 用当前 Milkdown CommonMark/GFM schema 和对应 remark 插件检查部分 Markdown 往返。这不替代项目自定义公式、图片扩展或完整桌面编辑器验收。
- 未运行应用、构建、完整类型检查或 Windows 桌面交互验收。此前保存流程的回归测试也不能证明全部 Markdown 与右键能力已通过验收。

## 判断一项 Markdown 能力是否健全

一项能力应同时回答三件事：

1. 显示：所见即所得和分栏预览分别显示什么，错误输入怎样回退。
2. 编辑：能否创建、修改、删除、复制粘贴、撤销和重做。
3. 保存：保存、重新打开和切换模式后，语义、正文与必要属性是否保留。

例如，公式能显示不代表能通过界面修改公式源码；Mermaid 在所见即所得中显示为可编辑代码块，是当前明确的产品行为，应当在能力表中写清楚。

## 保存往返的已知边界

所见即所得编辑后会重新序列化整个文档。显示正确的文件，也可能在编辑一个普通段落后发生其他位置的改写。

- 引用式链接转为行内链接通常属于格式规范化，目标地址和链接文字仍在。
- 未使用的链接定义会被当前 CommonMark/remark 链路移除，应评估是否需要保留。
- 代码围栏的 `js title="example" {1}` 只保留 `js` 和代码正文，标题、行标记等 info 元数据丢失。这类元数据不属于当前明确支持的功能，但不能把原文件的保真能力视为已完成。
- 列表标记、空行等也可能被规范化。验收应区分允许的格式变化与正文、地址、属性的实际损失。
- 单个 HTML 图片的 `width`、`height` 等属性也没有完整保留：转换器只读取 `src`、`alt`、`title`、`zoom` 和对齐。需明确只支持项目的图片约定，或扩展保存策略。
- 脚注、任务状态、表格列对齐在本次依赖层往返实验中保留；这不是所有扩展往返通过的证明。

## 审计基线右键的具体问题

当前菜单只接收 `hasSelection`、`inCodeBlock`、`canConvertToParagraph`，不能描述图片、链接、表格单元格、公式等目标。

| 优先级 | 问题 | 可复现结果 | 位置 |
| --- | --- | --- | --- |
| 先修 | 右键粘贴优先使用内部缓存 | 在 Lume 复制 A，然后到其他应用复制 B，再右键粘贴仍可能得到 A；缓存路径也绕过图片/Markdown 粘贴插件 | `wysiwyg/editorCommands.ts` 的 `clipboardText`、`paste` |
| 先修 | 旧选区与右键位置没有归属规则 | 选中第一段，再右键第二段，命令仍可能作用于第一段 | `WysiwygPane.vue` 的 `openContextMenu` |
| 先修 | 插入与转换语义混合，转换抽取纯文字 | 对带加粗、链接、图片或多段内容执行标题/列表/引用操作，原结构被重建为纯文字 | `wysiwyg/editorCommands.ts` 的 `insertHeading`、`insertList`、`insertBlockquote` |
| 后续 | 图片、表格、链接、公式没有专属菜单 | 图片没有替换/地址/说明，表格没有行列操作，公式没有编辑源码 | `overlays/EditorContextMenu.vue` |
| 后续 | 代码与正文共用插入菜单 | 在代码内仍展示表格、图片等块级动作，实际目标和结果不清楚 | `overlays/EditorContextMenu.vue`、CodeMirror NodeView |
| 后续 | 无命令可用性状态 | 撤销、重做或当前结构不支持的动作始终可点击 | `overlays/EditorContextMenu.vue`、`wysiwyg/editorCommands.ts` |
| 后续 | 子菜单键盘和边界处理不足 | 主菜单统计包含隐藏子菜单按钮；子菜单固定向右；`aria-expanded` 固定为 false | `overlays/EditorContextMenu.vue` |

## 建议的目标规则

先确定右键操作谁，再生成菜单。不同场景可以共用一个菜单组件，不需要为每个内容复制一套界面。

1. 区分所见即所得、源码编辑、只读预览模式。
2. 右键命中当前文本选区内部时保留选区；命中已有多单元格选区内部时保留单元格选区。
3. 右键落在旧选区外时，改为操作点击位置或点击对象。
4. 识别图片/公式、链接、代码块、表格单元格、列表/引用/标题、正文/空白。
5. 保留所在容器信息：例如链接可能位于表格单元格中，不应只能二选一。图片节点、文本选区和多单元格选区也应分别表示。
6. 菜单由“目标专属动作 + 可执行的通用动作”组成。执行时恢复目标选区，并确认仍属于当前文档；切换文档或删除对象后关闭菜单。

建议集中保存一个上下文对象：模式、命中位置、目标类型、容器链、选区类型、可执行命令集合。菜单展示和命令执行都使用该上下文，避免在组件里继续堆叠布尔开关。

## 建议的菜单矩阵

以下是目标行为，不代表这些命令已实现。

| 右键场景 | 专属动作 | 规则 |
| --- | --- | --- |
| 选中文字 | 复制、剪切、加粗、斜体、删除线、行内代码、链接、清除格式 | 保留命中选区；代码内不提供行内格式 |
| 正文/空白 | 转为标题/列表/引用；插入图片、表格、代码块 | “转为”操作当前块，“插入”新增内容，不隐式替换所选正文 |
| 标题 | 调整级别、转为正文 | 保留标题内格式和链接 |
| 列表/任务项 | 改变类型、缩进/减少缩进、切换完成状态、退出列表 | 保留多项和嵌套结构 |
| 引用 | 退出引用、转为普通块 | 保留内部多段和行内格式 |
| 表格单元格 | 插入/删除行列、列对齐、删除表格 | 区分单元格文字选择和多单元格选择 |
| 链接 | 打开、复制地址、编辑、移除链接 | 命中文本选区时优先选区操作；地址操作只作用于目标链接 |
| 图片 | 替换、复制地址/Markdown、编辑说明、对齐、恢复尺寸、删除 | 对目标图片建立 NodeSelection，不提供文字加粗 |
| 代码正文/块 | 复制选中代码/整块代码、粘贴纯文本、语言设置、在前后插入段落 | 区分 CodeMirror 文本选区和整块目标；不在代码正文中插入表格等富文本块 |
| 数学公式 | 编辑源码、复制源码、删除 | 直接操作原子公式节点 |
| 源码编辑 | 复制、剪切、粘贴、全选、可选语法辅助 | 操作原始 Markdown 选区 |
| 只读预览 | 复制、打开/复制链接、复制代码、图片地址 | 不提供修改命令 |

通用动作按能力显示或禁用：粘贴、撤销、重做、全选。每个动作都应能解释会修改哪个目标。

## 推荐实施顺序

1. 先修剪贴板、选区归属和结构保持；这些影响现有内容的正确性。
2. 固定核心 Markdown 支持范围，补齐任务列表的显示、勾选和预览，并给不支持的语法明确的保留策略。
3. 建立菜单上下文与可执行能力，依次接入图片、表格、链接、代码、公式的专属动作。
4. 用统一样例完成模式切换、复制粘贴、撤销重做、保存重开验收，再将路线图对应能力标记为已验收。

统一样例见 [`editor-capability-sample.md`](editor-capability-sample.md)。详细扩展验收要求仍参见 [`markdown-extension-acceptance.md`](markdown-extension-acceptance.md)。
