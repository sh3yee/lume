# Git 版本与同步实施规划

## 实施状态

第一阶段已实现本地仓库识别与初始化、暂存与提交、历史查看和单文件恢复。第二阶段已支持配置远程、获取远程状态和手动推送，入口与限制见[使用说明](git-version-control.zh-CN.md)。后续工作包括克隆、快进更新和合并冲突处理。

## 目标与边界

让本地文件夹工作区具备版本管理、远程同步和冲突处理能力。继续直接使用普通文件；关闭 Git 功能后，本地编辑与保存仍可使用。

通过系统 Git 和标准 HTTPS / SSH 仓库地址支持用户选择的托管服务及自托管仓库，不将远程接入绑定到某个平台。功能仅用于桌面应用。第一阶段要求设备已安装 Git，缺失时给出可理解的提示。

本规划分阶段实施。第一阶段交付本地版本管理，第二阶段交付远程连接和基本同步，第三阶段交付合并与冲突处理。

## 第一阶段：本地版本管理

### 使用入口

- 在工作区文件栏增加「版本」入口，打开独立版本管理面板。
- 自动识别当前工作区的仓库、分支、变更、暂存区和未完成操作。
- 普通文件夹可以初始化为本地仓库；已有仓库直接使用。
- 如果工作区位于更大仓库的子目录，明确展示仓库根目录与作用范围；第一版仅允许在仓库根目录进行写操作，避免提交工作区外的文件。
- 没有 Git、目录不可访问、Git 检查失败分别给出提示，不能将检查错误误判为普通文件夹。

### 变更、暂存与提交

- 展示新增、修改、删除、重命名文件，包含图片及附件，不依赖仅显示 Markdown 的文件树。
- 区分已暂存与未暂存内容，提供明确的暂存和取消暂存操作。读取并保留用户通过其他工具建立的暂存区，部分暂存必须能在界面中区分。
- 点击文件查看源码差异；二进制文件显示说明，不强行按文本解码。
- 提交仅包含已暂存内容，提交前展示范围并要求填写说明。
- 读取已有 Git 作者信息；需要补充时允许在当前仓库保存姓名和邮箱，不修改全局设置，不增加 AI 署名。
- 提交失败时保留当前变更与暂存状态，允许修改说明或配置后重试。
- 检测未解决冲突、合并、变基等操作；第一阶段提供状态与提示，不代替外部工具完成这些流程。

### 历史与文件恢复

- 分页查看当前分支提交历史，显示作者、时间、说明与变更文件。
- 查看某次提交的差异及其中单个文件的文本内容。
- 从历史恢复单个普通文件，恢复结果作为未暂存修改，不移动分支指针、不重写历史。
- 恢复前展示明确的文件与版本，覆盖本地内容前单独确认；第一版不提供整个仓库回退。
- 不通过历史条目删除当前文件；不恢复符号链接、子模块或越出仓库的路径。

### 保存与文件监听协调

- 复用编辑器内容刷新机制，版本操作前将尚未写回的输入同步到文档模型。
- 提供共享的文件操作协调器：版本操作等待正在执行的保存结束，并阻止新的文档保存与工作区写操作交错。
- 暂存前先保存有路径的工作区文档；保存失败、磁盘版本冲突或无法落盘时停止暂存。未命名草稿仍保留在草稿系统，不擅自决定路径。
- 历史恢复期间暂停外部变更处理，完成后更新已打开文档的内容与保存基准，再处理文件树刷新与后续事件。
- 自动保存、手动保存和版本恢复遵循同一协调规则，避免恢复后被旧编辑器内容覆盖。
- 用户继续输入时不得将新内容误标为已保存；恢复覆盖确认与实际写入之间须再次检查文件和编辑状态。

### 技术结构

- `src/features/git/`：版本面板、变更/历史展示、交互状态与业务操作。
- `src/platform/tauri/git.ts`：明确的命令参数及响应类型。
- `src-tauri/src/commands/git.rs`：轻量 Tauri 命令边界，后台执行阻塞任务。
- `src-tauri/src/services/git/`：Git 进程执行、仓库状态、历史与写操作。
- Git 调用使用参数数组，不拼接 shell；仓库操作串行化。
- 使用稳定的机器输出格式和 NUL 分隔路径，支持中文、空格等文件名。
- 对仓库根目录、Git 元数据路径、文件路径、提交对象及输出规模进行边界校验；Git 子进程必须有执行时限，不无限等待交互输入。
- 沿用项目中英文界面和主题样式，不新增第三方依赖。

### 验收标准

- 普通文件夹、已有仓库、尚无首次提交、独立 HEAD 和未完成合并能正确区分。
- 初始化、暂存/取消暂存、提交与历史查询形成完整可用流程。
- 已有暂存内容不会因打开面板而改变；文件部分暂存时能够分别查看两部分差异。
- 图片与附件可参与提交；中文、空格和重命名路径可正确处理。
- 历史恢复不修改 HEAD 或暂存区，打开中的文档与磁盘结果一致。
- 失败操作有反馈，保存失败或冲突时停止后续写操作；快速切换工作区不会让旧请求覆盖新面板状态。
- 完成适合此次改动的静态检查与隔离仓库行为验证，不在项目保留临时测试文件或验证产物。

## 第二阶段：远程连接与基本同步

- 支持克隆远程仓库至新目录，以及为已有仓库配置远程地址和跟踪分支。
- 复用系统 Git credential helper、SSH 配置和 agent；补齐首次认证、口令及主机确认的交互，凭据不进入普通偏好设置或日志。
- 区分作者信息与远程认证；不固定远程名称或默认分支。
- 获取远程状态并展示本地领先、远程领先及分叉情况；离线时明确标识状态可能过期。
- 同步前完成保存并处理未提交变更。先支持获取更新、快进更新与推送；分叉时给出明确提示。
- 推送失败保留本地提交，允许重试；远程并发更新后重新获取状态，不使用强制推送覆盖。
- 本地和远程历史无关时引导克隆后导入，不自动强行合并。

## 第三阶段：合并与冲突处理

- 为历史分叉提供明确的合并流程，保留本地已提交内容。
- 展示共同基础、本地、远程与可编辑合并结果，按冲突块处理并标记解决。
- 冲突文件使用源码合并界面，暂停所见即所得编辑和普通自动保存。
- 支持文本冲突、修改/删除冲突、重命名相关冲突；二进制文件提供版本选择与另存副本。
- 支持继续合并、中止合并及重启后的状态恢复，结束后刷新文档与文件树。
- 完善网络失败、认证失败、锁占用、取消操作和恢复反馈。

## 后续评估

在手动流程可靠后评估自动获取远程状态、自动提交和自动同步。自动保存、创建本地版本、上传远程分别设置，默认由用户主动提交与同步。复杂分支管理、子模块、Git LFS 配置和整库历史重写不纳入当前三个阶段的主要交互。
