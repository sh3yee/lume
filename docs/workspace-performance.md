# 工作区扫描与监听性能基线

本文档记录 Phase 5 工作区能力的性能约束和手动基线方法。

## 当前实现

- Rust 后台线程每 `750 ms` 获取一次 Markdown 文件快照。
- 单个工作区最多扫描 `5000` 个 Markdown 条目，最大递归深度为 `32`。
- 跟踪目录以及 `.md`、`.markdown` 文件，跳过符号链接和其他文件。
- 变化按批次发送，普通编辑按键不会跨进程调用 Rust。
- 前端记录最近一次变化扫描耗时 `lastScanDurationMs`，仅在存在变化时更新。

## 性能目标

| 场景 | 目标 |
| --- | --- |
| 1000 个 Markdown 文件初次扫描 | 小于 500 ms |
| 5000 个 Markdown 文件初次扫描 | 小于 1500 ms |
| 单文件外部变化检测 | 小于 2 秒 |
| 无变化监听 | 不产生前端事件，不影响连续输入 |
| 变化批次处理 | 不阻塞编辑主线程超过 50 ms |

## 手动基线步骤

1. 准备分别包含 1000 与 5000 个 Markdown 文件的测试目录。
2. 打开工作区，使用开发者工具 Performance 面板记录文件树出现时间。
3. 连续输入 30 秒，确认监听期间无周期性长任务或明显卡顿。
4. 在外部编辑、创建和删除文件，记录从磁盘操作到界面更新的延迟。
5. 对 dirty 文档制造外部修改，确认冲突弹窗出现且本地内容未被覆盖。
6. 将结果、操作系统、磁盘类型和工作区规模记录到发布验收报告。

## 当前自动基线

- 环境：Windows，本地开发磁盘，Rust debug 测试构建。
- 规模：1000 个 Markdown 文件。
- 扫描耗时：11 ms。
- 测试入口：`workspace_scanner::tests::measures_thousand_file_scan_baseline`。
- 结果仅用于发现后续性能退化；发布前仍需按上述步骤进行桌面交互基线。
