# Lume

Lume 是一款面向个人创作与本地知识管理的桌面 Markdown 编辑器。

目标是在保持 Markdown 源文件可移植、可版本管理的前提下，提供低输入延迟、精致排版和可靠的本地文件体验。

## 产品原则

- 本地优先：文档归用户所有，直接读写本地 `.md` 文件。
- Markdown 优先：以源码编辑为核心，预览是对 Markdown 的可靠呈现。
- 输入优先：键入、光标、选区和撤销操作不能被预览渲染阻塞。
- 渐进增强：复杂能力按需加载，基础编辑体验保持轻量。
- 可移植：不将核心内容锁定在私有数据库或专有格式中。

## 技术架构

| 层级 | 技术选择 | 职责 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 窗口生命周期、命令桥接、打包与权限模型 |
| 原生能力 | Rust | 本地文件 I/O、文件监听、全文搜索、索引、设置与数据库 |
| 前端界面 | Vue 3 + TypeScript + Vite | 工作台布局、主题、交互状态与组件化界面 |
| 编辑内核 | CodeMirror 6 | Markdown 源码输入、选区、IME、撤销、快捷键与语法高亮 |
| Markdown 预览 | markdown-it | CommonMark/GFM 扩展解析与 HTML 输出 |
| 后台计算 | Web Worker | 预览解析、目录提取、词数统计等非交互任务 |
| 代码高亮 | Shiki | 在空闲时为预览代码块进行高质量高亮 |
| 数学公式 | KaTeX | 快速渲染 LaTeX 数学公式 |
| 数据存储 | SQLite | 设置、工作区记录、索引和轻量元数据 |

## 核心设计

编辑器不能将每次按键都发送到 Rust 或触发完整预览重绘。

```text
CodeMirror 6
    |
    | 输入事件
    v
前端轻量状态更新
    |
    | 150-300ms 防抖
    v
Web Worker: markdown-it 解析、目录与统计
    |
    v
预览区域局部更新
    |
    +--> 浏览器空闲时: Shiki、Mermaid 等重型渲染

Rust / Tauri
    |
    +--> 文件读写、文件监听、搜索索引、SQLite、系统集成
```

- CodeMirror 6 保持在前端：输入法、光标和选区依赖 WebView DOM 交互，跨进程传递每次输入会损害响应速度。
- Worker 负责文本计算：避免 Markdown 解析阻塞主线程。
- Rust 处理系统级与大规模任务：文件树、搜索、索引、Git 集成和长期后台工作。
- 大文档按章节切分预览：只渲染可视区域附近内容，避免大规模 DOM 更新。

## 路线图

### Phase 0: 项目基础

目标：建立可持续迭代的桌面应用骨架。

- [ ] 初始化 Tauri 2、Rust、Vue 3、TypeScript 与 Vite。
- [ ] 建立目录约定、ESLint、Prettier、提交规范与基础 CI。
- [ ] 定义设计 Token：颜色、排版、间距、阴影、圆角和明暗主题。
- [ ] 搭建应用壳：标题栏、侧栏、编辑区、预览区和状态栏。
- [ ] 建立 Tauri 命令边界与错误处理规范。

验收标准：应用可在 Windows 开发环境启动，基础布局在常见窗口尺寸下稳定响应。

### Phase 1: 可用的单文档编辑器

目标：完成快速、可靠的 Markdown 编辑闭环。

- [ ] 集成 CodeMirror 6 与 Markdown 语言支持。
- [ ] 实现源码编辑、行号、当前行、高亮主题、撤销重做和常用快捷键。
- [ ] 通过 markdown-it 实现防抖预览。
- [ ] 支持 GFM 基础语法：标题、列表、表格、任务列表、删除线和引用。
- [ ] 提供编辑、分栏、预览三种工作模式。
- [ ] 实现新建、打开、保存、另存为与未保存更改提示。
- [ ] 提供字数、字符数、阅读时长和光标位置状态。

验收标准：可打开、编辑、保存普通 Markdown 文件；连续输入时界面无明显卡顿，预览在停止输入后及时同步。

### Phase 2: 工作区与文件体验

目标：让用户能够管理一个本地 Markdown 工作区。

- [ ] 支持打开文件夹并展示可折叠文件树。
- [ ] 支持新建、重命名、移动和删除文档。
- [ ] 使用 Rust 文件监听同步外部修改。
- [ ] 维护最近打开的工作区和文件。
- [ ] 支持图片、链接和附件的相对路径插入。
- [ ] 使用 SQLite 存储工作区元数据和用户设置。
- [ ] 增加崩溃恢复与自动保存草稿。

验收标准：用户可将现有 Markdown 文件夹作为工作区稳定使用；外部编辑文件后可检测并提示处理。

### Phase 3: 高质量阅读与写作

目标：将预览体验提升到可长期阅读和写作的水平。

- [ ] 支持目录导航与编辑区、预览区滚动同步。
- [ ] 支持明暗主题、专注模式、可配置字体和排版宽度。
- [ ] 支持 KaTeX 数学公式、Mermaid 图表和脚注。
- [ ] 引入 Shiki 代码高亮，并在空闲阶段执行。
- [ ] 支持文档内快速搜索、替换和命令面板。
- [ ] 支持导出 HTML 与 PDF。

验收标准：复杂文档在阅读与编辑模式下排版一致，扩展内容不会明显影响正常输入。

### Phase 4: 搜索、索引与效率工具

目标：提升多文档场景下的信息检索效率。

- [ ] 在 Rust 中构建工作区全文索引。
- [ ] 支持文件名、正文、标题和标签搜索。
- [ ] 提供快速打开、最近文件和反向链接基础能力。
- [ ] 支持标签、收藏与文档大纲。
- [ ] 评估 Git 状态展示、差异预览与版本历史。
- [ ] 对超大文件引入分块解析与预览虚拟化。

验收标准：中等规模工作区可快速返回搜索结果，搜索与索引不会阻塞编辑操作。

### Phase 5: 同步与扩展生态

目标：在不牺牲本地优先原则的前提下扩展能力。

- [ ] 设计可选的同步接口，默认不上传用户内容。
- [ ] 支持 WebDAV、Git 或自托管同步方案的可行性评估。
- [ ] 定义受控插件 API，隔离插件权限与运行环境。
- [ ] 支持自定义主题、模板和快捷键配置。
- [ ] 建立性能基准、错误收集与隐私透明机制。

验收标准：同步和扩展均为可选能力，不影响离线核心编辑功能。

## 非目标

以下能力不进入早期版本范围：

- 以富文本为核心的所见即所得编辑。
- 实时多人协作。
- 云端账号体系和强制在线服务。
- 为兼容性牺牲本地 Markdown 文件结构。
- 在未验证需求前引入复杂插件系统。

## 性能预算

| 场景 | 目标 |
| --- | --- |
| 应用冷启动 | 常见桌面环境下尽快进入可编辑状态 |
| 普通键入 | 主线程不执行完整 Markdown 解析 |
| 预览更新 | 采用防抖与分级渲染，避免连续全量刷新 |
| 大文档 | 分块处理并限制单次 DOM 更新范围 |
| 文件搜索 | 在 Rust 后台执行，结果增量返回 |

## 近期优先级

1. 完成 Phase 0 的项目骨架和设计 Token。
2. 实现 Phase 1 的单文档编辑、预览与安全保存。
3. 以真实 Markdown 文档验证输入延迟、预览同步和内存占用。
4. 完成 Phase 2 的工作区能力，再推进复杂 Markdown 扩展。
